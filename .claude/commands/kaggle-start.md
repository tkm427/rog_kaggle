セッション開始の必須手順。**今日の作業を始める前に、以下を順に実行して報告すること。**

## 1. ダッシュボードを再生成する（最初にやる）

```bash
python3 scripts/build_dashboard.py
```

標準出力に「フェーズ / 未達ゲート / 警告件数」が出る。**この数値を報告の根拠にする**
（md を読んで自分で数え直さない）。生成物は `outputs/dashboard.html`。

## 2. 読む

1. `CLAUDE.md`
2. `docs/{competition}/strategy.md`（時間予算ブロックと今週の方針）
3. `docs/{competition}/experiments.md`（現在のフォーカス・実験一覧・CV-LB 表）
4. `docs/{competition}/formulations.md`（定式化ボード）

`{competition}` は `docs/` 直下で `_templates` 以外のディレクトリ。複数あれば最も新しいもの。
どれか無ければ「Phase 0 未完了」として報告する。

## 3. 報告（この形式で、これ以上長くしない）

```
■ Phase ? — <フェーズ名>
  未達ゲート: R2, R5 （無ければ「なし」）

■ 時間予算
  残り N 日 / 1実験 D 日 → 残り実験可能数 ? 本 / 計画段数 ? 本
  best X → 目標 Y（残距離 ?）

■ 警告
  ⚠ 同一定式化 ? 連続（F?）        ← 2 以上で表示
  ⚠ アーキテクチャ族 1 系統のみ      ← T1 未達で表示
  ⚠ 今週の提出 0 回                 ← 0 で表示
  ⚠ 未読 Discussion ? 件            ← R2 未達で表示
  ⚠ 計画段数 > 残り実験可能数        ← 超過で表示

■ 今日の候補（最大3つ・推薦に ★）
  ★ 1. …
    2. …

■ 詳細: outputs/dashboard.html
```

**md の内容をチャットに貼らない。** 詳細はダッシュボードのパスを示すだけにする。

## 4. 判定ロジック（ダッシュボードが計算済み。食い違ったらスクリプトを疑う）

- **フェーズ**: CLAUDE.md 第3節のゲートを上から評価し、最初に未達のゲートがあるフェーズが現在地
- **未読 Discussion**: `research/discussions.md` の `[ ]` の数 + 「ゲート宣言」の未チェック数
- **同一定式化の連続数**: `experiments.md` の実験一覧を下から見て、「失敗の層 ≠ 該当なし」または
  「OOF が改善していない」実験が同じ定式化 ID で何本続いているか
- **アーキテクチャ族の数**: `experiments.md` と `conf/model/` から、提出可能な状態にある系統を数える
- **今週の提出回数**: `experiments.md` の CV-LB 表で直近 7 日以内の行数
- **残り実験可能数**: `strategy.md` の時間予算ブロック。古ければ今日の日付で再計算して更新する

## 5. 行動

- **未達ゲートがあれば、それを埋める作業を今日の第一候補（★）にする。** 実験の続きより優先
- 警告が出ている場合は、**作業を始める前に人間の判断を仰ぐ**（CLAUDE.md 第1節）
- 今日の目的を **1 つに絞って** TodoWrite に分解する
- **判断を仰ぐときは AskUserQuestion を使う**（散文で選択肢を並べない）
- `strategy.md` の時間予算ブロックが古ければ更新する

コンペが終了している場合は「終了済み」と報告し、ふりかえりが未作成なら postmortem を提案する。
