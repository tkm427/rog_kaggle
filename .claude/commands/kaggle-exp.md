新しい実験を開始する。狙い: `$ARGUMENTS`

**コードを書く前に以下を全部済ませること。** 「とりあえず動かす」実験は禁止（CLAUDE.md 第11節）。

## 1. 2 ストライク判定（最初にやる）

1. `docs/{competition}/experiments.md` の実験一覧を下から読む
2. 直近 2 実験の**定式化 ID** と、それぞれが改善したか（失敗の層が「該当なし」か）を確認する
3. 今回の実験がどの定式化に属するかを決める

**直近 2 実験が同一定式化で、いずれも改善していない場合 → 2 ストライク。**
その場合は**ここで停止し**、以下を提示して人間の判断を仰ぐ:

- 現状: 「F? で ? 連続ゼロ改善」という事実と各実験の実測値
- `formulations.md` から**別定式化の候補を最大 3 つ**、推薦 1 つ付きで提示
- 「それでも同じ定式化を続ける」選択肢も提示するが、**推薦にはしない**

提示は **AskUserQuestion** で行う（散文で読ませない）。

承認を得ずに同一定式化の 3 本目に着手してはならない。

## 2. `expXXX.md` を書く

`docs/{competition}/experiments/_template.md` をコピーして次の番号で作成し、
**着手前に**以下を埋める:

- **所属する定式化**（F?）と 2 ストライク判定の結果
- **仮説**（1〜2 文）
- **事前予測**（全体 / 層別 / 予測を外したら何が分かるか）
- **ゲート基準** — `strategy.md` の時間予算から
  「現在 best X / 目標 Y / 残距離 D」を引き、**残距離の何 % を詰めれば合格か**で置く。
  **null model 比で置かない**（CLAUDE.md 第4節）
- **設定**（config・CLI オーバーライド・W&B Run 名 `YYYYMMDD_{model}_{変更点}`）

## 3. 実行

- 既存 config を書き換えず、CLI オーバーライドか新規 config で対応する
- 学習の実行は人間。**コマンドを出力するだけにする**
- 長時間の学習は W&B の run 名を先に確定しておく

## 4. 完了時

- `expXXX.md` の「実際の結果」「**失敗の層**」「考察」「次のアクション」を埋める
- `experiments.md` の実験一覧に 1 行追加、「現在のフォーカス」を更新
- `formulations.md` の「各実験がどの定式化に属するか」表に 1 行追加。
  定式化を棄却する場合は**実測値を根拠として書く**
- 推論経路を変更した場合は `kaggle_kernel/` の notebook に同期する（CLAUDE.md 第10節）
- 提出した場合は CV-LB 表に**日付つきで**追記
- ゲートが動いたら `gates.md` の宣言と根拠を更新する
- `python3 scripts/build_dashboard.py` を実行し、**チャットには結果 1 行とダッシュボードのパスだけ**返す
